# Архитектура v0.1

```text
ПК сотрудников (браузер / SMB для афиш)     Посетительские ПК (браузер)
          │                                        │
          └────────────── локальная сеть ─────────┘
                               │
                    DESKTOP-OBLAKO (Windows)
                               │
                     единый HTTPS origin
                               │
                    ┌──────────┴─────────┐
                    │ Vue 3 / Vite SPA   │  /screen /editor /admin
                    │ Fastify REST API   │  /api/*
                    │ WebSocket события  │  ревизии публикаций
                    └──────────┬─────────┘
                               │
                 PostgreSQL 18 / media storage
                               │
                import jobs / FFmpeg / snapshots
```

## Решения

- Один сервер в ДК, несколько терминалов и сотрудников; никаких отдельных desktop EXE.
- Стартовая структура `apps/web` + `apps/api`, TypeScript и общие типизированные контракты на следующем этапе.
- Данные редактора и опубликованные снимки разделены. Публикуемый снимок версионирован; клиент не смешивает частичные изменения.
- Схема сущностей: `users`, `roles`, `sections`, `pages`, `blocks`, `templates`, `sources`, `media`, `events`, `collectives`, `schedule_entries`, `revisions`, `publications`, `terminals`, `audit_log`.
- Каждая запись имеет `id`, `revision`, `updated_at`. Для карточек расписания используется серверный UUID и контроль ревизий; перемещение кнопок не изменяет их идентичность.
- SMB-папка — дополнительный источник; поток папки и браузерное редактирование не должны перетирать друг друга: разрешается отдельно назначить владельца полей и источник контента.
- API доступен с LAN только после авторизации и сетевого ограничения. На этапе 00 API слушает `127.0.0.1`.
- Для production: сборка Vue раздаётся с того же происхождения, что API (через HTTPS reverse proxy); URL/порт задаются при развёртывании после проверки служб `DESKTOP-OBLAKO`.
- Сервер не должен менять существующие ресурсы `Kuluari`, `Oblako`, `print$`, пользователей SMB и службы без отдельного согласования.

## Ожидаемые технологические решения

- **Frontend:** Vue 3 + TypeScript + Vite 8 + Router; Pinia — с появлением сложного состояния.
- **Backend:** Node.js 26 LTS + Fastify 5; явная JSON Schema валидация в будущих POST/PUT.
- **DB:** PostgreSQL 18, транзакции публикаций и миграции.
- **События:** WebSocket + резервный polling; события несут `publication_revision`.
- **Медиа:** иммутабельные файлы по content hash, антивирус/валидация, FFmpeg-конвертация для браузера.
- **Сервис Windows:** отдельная служба с автозапуском, неповышенные права, отдельная папка данных; способ установки согласовать после preflight.

## Границы текущего каркаса

На этапе 00 реализованы GET `/api/health`, GET `/api/public/navigation` (демо), Vue-маршруты `/screen`, `/editor`. Нет БД, логина, записи, WebSocket, импорта и production HTTPS. Показывать демо как действующую систему запрещено.
