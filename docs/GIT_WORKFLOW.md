# GitHub workflow — RatiborK/Kioskinfo

- Репозиторий: https://github.com/RatiborK/Kioskinfo
- **Сейчас репозиторий public**: НЕ помещать туда секреты, учётные данные, реальные персональные данные сотрудников, резервные копии БД, приватные афиши, локальные IP, токены и `.env`.
- Ветка по этапу: `stage/00-navikultura-architecture`, `stage/01-auth-persistence` и т. д.
- Не разрабатывать напрямую в `main`. Один завершённый этап — PR и отчёт приёмки.
- PR должен содержать цели, список файлов, тесты и известные ограничения.
- GitHub Actions проверки: типы TypeScript/Vue, тесты Fastify, сборка приложения. Лабораторный PASS не заменяет приёмку на реальном ПК.
- Каждая следующая версия меняет `docs/ROADMAP.md` и фиксирует новый результат.
- Для релизов в ДК — отдельный тег и резервная копия перед обновлением, поэтапное развёртывание; не выполнять автодеплой на рабочий сервер только по push.
