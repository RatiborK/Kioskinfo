# НавиКультура — локальная разработка в VS Code

## Цель

Исходный код разрабатываем на рабочем ПК в `%USERPROFILE%\Navikultura`. Сервер `DESKTOP-OBLAKO` до готовности проекта не трогаем.

## Один раз на компьютере

1. Установить **Node.js 26.x LTS** и **Visual Studio Code**. Git уже установлен.
2. В PowerShell из каталога проекта выполнить `node -v`, `npm -v`, `git status --short --branch`.
3. В ветке `stage/00-navikultura-architecture` получить обновления: `git pull --ff-only` (только при чистой рабочей копии).
4. Установить зависимости: `npm install --no-audit --no-fund`.
5. Проверить: `npm run check`.
6. Открыть редактор: `code .`.

## Запуск и наблюдение

В VS Code: **Terminal → Run Task → Navikultura: Start API + Web**. 
Либо два терминала:
- `npm run dev:api` — сервер API на 127.0.0.1:3100;
- `npm run dev:web` — Vite на 127.0.0.1:5173.

В браузере:
- http://127.0.0.1:5173/screen — экран посетителя;
- http://127.0.0.1:5173/editor — рабочий кабинет (на этапе 00 прототип без сохранения данных).

Auto Save в VS Code сохраняет исходники на диск после паузы около 1,2 с. Vite HMR сразу показывает обновлённый интерфейс в браузере. API перезапускается через tsx watch.

## Git и изменения

**Auto Save не равен коммиту Git.** Не публиковать на GitHub каждое промежуточное нажатие клавиши.

- Изменения, сделанные ассистентом в рабочей ветке GitHub: `git pull --ff-only` при чистом дереве.
- Для локальных изменений сначала `git status --short`, затем `git add -A`, `git diff --cached --stat`, `git commit -m "описание"` и `git push`.
- Перед публикацией убедиться, что в изменениях отсутствуют пароли, токены, данные сотрудников и внутренние документы.
- Никогда не делать `git reset --hard`, `push --force`, автоматический merge или обновление `main` без отдельного согласования.
- Рабочие данные, файлы загрузки, резервные копии и `.env` исключены из Git.
- Для синхронизации не применять `pull --rebase` или `--autostash` без предварительного осмотра изменений.
- Если локальные и удалённые изменения одновременно затрагивают одни файлы — остановиться и согласовать конфликт.

## Проверка завершённости этапов

`npm run check` должен завершаться успешно; только затем делать приёмочный Pull Request. 

До Stage 01 нет рабочей авторизации, PostgreSQL и сохранения данных; Stage 00 не предназначен для эксплуатации.
