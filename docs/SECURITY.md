# Минимальные принципы безопасности

- Кабинет сотрудника `/editor` и администрирование `/admin` нельзя делать записывающими или доступными по сети, пока нет аутентификации и авторизации.
- Роли: viewer, editor, publisher, admin; доступы проверяются на сервере, а не только скрытием кнопок.
- Автосохранение: debounce 600–1000 мс; сервер возвращает revision; при конфликте 409 сохраняем обе версии/предлагаем выбор.
- Шаблоны, файлы, изображения, видео и Excel обрабатываются как недоверенные данные; ограничение размера, проверки MIME и сигнатуры файла, песочница конвертера.
- Автозагрузка через общую папку не должна иметь права запускать скрипты или переписывать код приложения; путь и права сервиса ограничены.
- Критически важное удаление подтверждается, журналируется, доступно восстановление из резервной копии.
- Пароли не хранятся как текст. Секреты и служебные настройки не коммитятся.
- Клиенты получают только опубликованные публичные данные. Логи не содержат паролей, токенов или личных данных сверх необходимого.
- Сервер должен стартовать с минимальными правами; будущий HTTPS и правила Windows Firewall обязательны для LAN-развёртывания.
