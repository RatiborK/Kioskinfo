# Stage 02 — Автоматические афиши / кандидат

## Назначение

Папка `content/posters` (либо `POSTERS_DIR`) становится источником афиш и MP4. Система не использует изображения старой системы как актуальные афиши без проверки.

## Реализовано

- GET `/api/public/posters` отдаёт безопасный каталог файлов, полученный из папки. Подтверждение имени, расширения и сигнатуры предотвращает публикацию случайных файлов.
- GET `/api/public/posters/:name/file` отдаёт файл, не раскрывая физический путь сервера.
- POST `/api/editor/posters` загружает до 8 МБ JPG/PNG/WebP только после входа сотрудника с правом editor/admin.
- DELETE `/api/editor/posters/:name` удаляет только верифицированную афишу с правом editor/admin.
- Экран `/screen` показывает изображения и MP4, перелистывает изображения каждые 8 секунд, проверяет каталог каждые 10 секунд.
- `/editor` позволяет добавить и удалить афиши через браузер после входа в Stage 01.
- Папка — источник истины: копирование или удаление через проводник отображается при следующем опросе; пустой каталог имеет понятное сообщение.

## Ограничения / следующие шаги

- MOV/AVI/MKV требуют серверной конвертации в браузерный MP4, эту функцию ещё предстоит добавить. В Stage 02 доступны изображения и MP4 с браузерно-совместимым кодеком.
- Большие видео копируются непосредственно в папку. Загрузка видео через браузер не реализована.
- Каталог пока сортируется по названию; ручной порядок и график публикации — отдельный этап.
- Указание файла через сетевую папку `POSTERS_DIR` допускается только после настройки NTFS/SMB-прав доступа; не использовать общий ресурс на весь доступ без ограничений.
- Срок отображения одного видео определяется его завершением; если видео кодек не поддерживается, автоматическое перелистывание этой позиции требует доработки.
- Для поддержки истории удалённых афиш понадобится архив публикаций; пока удаление файла физическое.
- Сервер Stage 01 требует PostgreSQL и учётной записи; интеграция с живой базой локально не подтверждена.
