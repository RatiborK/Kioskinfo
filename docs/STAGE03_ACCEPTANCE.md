# Stage 03.1 — веб-редактор расписания

## Изменённый подход

Excel больше не является источником расписания. Сотрудник создаёт и изменяет карточки в `/editor`. Каждая опубликованная карточка автоматически становится кнопкой на `/screen`.

## Реализовано

- Создание карточки из названия кнопки и коллектива без технического ID (генерируется UUID).
- Поля: название, коллектив, руководитель, время, кабинет, возраст, описание, оформление, порядок.
- Три шаблона, галочка наследования оформления первой кнопки.
- Автосохранение черновика через 800 мс; контроль ревизий, 409 при конфликте.
- Публикация отдельным действием, черновики скрыты от посетителя.
- Удаление карточки (подтверждение), доступ администратора.
- Локальное файловое хранилище `content/schedule/records.json` и временный пароль для разработки.
- PostgreSQL-провайдер и миграция `002_schedule_web.sql` для последующего LAN-развёртывания.
- Автоматическое обновление публичного расписания каждые 10 секунд.
- API-проверки прав доступа, ревизий, валидации, отката при повреждении файла.

## Ручная приёмка на ПК разработчика

- [ ] `npm.cmd run check` — PASS
- [ ] Локальный режим входа показывает одноразовый пароль в терминале API.
- [ ] Созданная карточка видна в списке редактора, но не на экране посетителя до публикации.
- [ ] После публикации кнопка появляется на `/screen` в течение 10 секунд.
- [ ] Редактирование формы сохраняется через 800 мс, браузер можно перезагрузить без потери данных.
- [ ] Карточка сохраняется после перезапуска API.
- [ ] Изменение без публикации не изменяет публичный текст.
- [ ] Наследование оформления следует первой опубликованной кнопке.
- [ ] Удаление скрывает опубликованную кнопку.
- [ ] Пароль и содержимое `content/` не оказываются в Git.

**Не выполнять развёртывание на DESKTOP-OBLAKO до PostgreSQL, TLS, тестов LAN и резервного копирования.**
