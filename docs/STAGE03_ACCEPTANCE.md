# Stage 03 — Excel → кнопки и карточки

## Реализовано

- Один XLSX-файл `content/schedule/raspisanie.xlsx` — источник расписания.
- Одна строка = одна кнопка с карточкой, привязанная к стабильному ID.
- Настройка темы по столбцу `Шаблон`: оранжевый / синий / нейтральный.
- При `Повторить стиль = Да` и пустом шаблоне строка наследует тему предыдущей записи.
- Веб-интерфейс `/screen` отображает расписание и подробности нажатой кнопки.
- Обновление каждые 10 секунд без перезапуска сервера.
- Синтаксические ошибки, дубликаты ID, неполные колонки и неверные шаблоны блокируют новую публикацию, сохраняя последнюю удачную версию.
- Нет опасных макросов, HTML из ячеек не исполняется.

## Ограничения этапа

- Редактирование XLSX производится сотрудником в Excel, а не в браузерной таблице.
- Произвольный визуальный конструктор и кастомные шаблоны — Stage 04; сейчас есть три стандартные темы.
- Включён автоматический режим публикации валидного файла; подтверждение/ролевые права импорта добавим позже.
- XLSX до 3 МБ и не более 300 строк; первый лист — «Расписание».
- Изображения коллективов и календарные исключения — позже.
- При ошибке обновления данные продолжат отображаться до ручного исправления файла.

## Локальная приёмка Windows

1. Остановить два запущенных dev-сервера через Ctrl+C.
2. Переключить репозиторий на `stage/03-excel-schedule` только при чистой рабочей копии.
3. Выполнить `npm.cmd install --no-audit --no-fund`, затем `npm.cmd run check`.
4. В VS Code запустить `Navikultura: Start API + Web`.
5. Скопировать `templates/Расписание_пример.xlsx` в `content/schedule/raspisanie.xlsx`.
6. Открыть `/screen`, нажать «Расписание», убедиться в наличии трёх демонстрационных карточек.
7. Переименовать кнопку во второй строке, сохранив ID, затем проверить автообновление (до 10 секунд).
8. Добавить строку, удалить строку, проверить соответствующее изменение кнопок.
9. Создать дублирующий ID — должен сохраниться предыдущий корректный список.
10. Не переносить на `DESKTOP-OBLAKO` до завершения проверки Stage 07.
