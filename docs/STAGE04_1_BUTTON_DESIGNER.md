# Stage 04.1 — визуальный конструктор кнопок расписания

## Что уже реализовано
В кабинете **Расписание** сотрудник выбирает цветовой шаблон и дополнительные параметры:
- Заливка: контур / сплошной цвет
- Форма: прямые углы / 16px / 36px
- Размер текста: обычный / крупный / очень крупный
- Выравнивание: слева / по центру

Предпросмотр в редакторе использует те же классы, что и экран посетителя.
Существующий флаг `inheritTheme` расширен до наследования *цвета и всех новых параметров* первого опубликованного элемента.
Для первой карточки шаблон наследования не применяется. Другие карточки могут наследовать его динамически после публикации первой.

## Сохранность данных
- `content/schedule/records.json`: старые карточки без `appearance` читаются со стандартным оформлением; исходный файл не переписывается при простом чтении.
- PostgreSQL: добавить колонку `appearance jsonb` миграцией `003_schedule_appearance.sql` после `002_schedule_web.sql`.
- Предыдущие опубликованные записи без appearance продолжают отображаться; поле нормализуется на сервере.
- Автосохранение 800 мс остаётся черновиком; публичные экраны показывают только опубликованные снимки.
- Внешний CSS, HTML, произвольные цвета и URL из формы не принимаются — только перечисленные значения.

## Приёмка на ПК разработки
1. Выбрать ветку `stage/04-button-appearance` и выполнить `npm.cmd run check`.
2. Открыть `http://127.0.0.1:5173/editor?tab=schedule`.
3. Создать «Танцы», выключить наследование и задать «Синий / Заливка / Скруглённые / Очень крупный / По центру».
4. Убедиться в мгновенном предпросмотре и автоматическом сохранении черновика.
5. Проверить, что экран посетителя до публикации не изменился.
6. Опубликовать и открыть `http://127.0.0.1:5173/screen` → «Расписание», проверить все четыре параметра.
7. Создать вторую кнопку с галочкой наследования, опубликовать. Проверить одинаковое оформление.
8. Изменить и сохранить первую кнопку без публикации: обе публичные кнопки сохраняют прежний стиль.
9. Опубликовать первую: на втором опубликованном элементе автоматически применяется новый стиль.
10. Перезапустить локальный API: карточки и оформление должны сохраниться.
11. Проверить вкладки «Афиши» и «Страницы», а также поведение узкого экрана.

## Отложено
Это этап **конструктора кнопок**, а не полнофункциональный редактор любых блоков страницы. Изображения, произвольная раскладка разделов, глобальные шаблоны и drag-and-drop запланированы следующим этапом.

**CI PASS — не равно проверке на целевом PostgreSQL и Windows.**
