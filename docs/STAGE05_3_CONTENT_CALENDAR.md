# НавиКультура — Stage 05.3: сохранение форм, документы и календарь

## Требования и реализация

### 1. Поля расписания и страниц
- Убрана логика таймера автосохранения через **800 миллисекунд** (не 8 секунд).
- При наборе текста поля **не отключаются** во время фонового запроса. Это устраняет потерю фокуса в момент автосохранения.
- Поле сохраняется после выхода из него (blur) или по явной кнопке **«Сохранить»**.
- Перед переключением страницы, карточки или вкладки редактор пытается сохранить черновик; при конфликте ревизии остаётся в форме с сообщением об ошибке.
- **«Опубликовать»** остаётся отдельным действием. Черновик не показывается посетителям до публикации.

### 2. Вход администратора
- На правой панели посетителя добавлена небольшая ссылка **«Вход в админку»** с замком.
- Открывает `/editor`. Публичная ссылка не даёт прав без логина/пароля.
- Если пользователь **не авторизован** и три минуты не трогает страницу входа, браузер возвращается к `/screen`.
- Активная сессия сотрудника **не сбрасывается** по этому гостевому таймеру.
- При вводе данных или касании отсчёт трёх минут начинается заново.

### 3. Документы ДК
- Публичная вкладка **«Документы ДК»** и вкладка администратора **«Документы»**.
- Категории: **Прейскурант цен**, **Положения**, **Льготы**, **Другие документы**.
- Загрузка через форму DOCX или PDF до 6 МБ.
- DOCX преобразуется библиотекой Mammoth в HTML, затем очищается `sanitize-html` по строгому списку разрешённых тегов. Сохраняются заголовки, таблицы, абзацы, списки, выделения. Ссылки/скрипты/стили из Word не допускаются.
- На посетительском экране DOCX показывается как аккуратно оформленный документ с типографикой и читаемыми таблицами. PDF показывается через встроенный просмотр PDF браузера (если доступен).
- Оригинал доступен отдельной кнопкой. Старый `.doc` необходимо сохранить в Word/LibreOffice как `.docx`.
- Файлы и каталог хранятся в `content/documents`, который игнорируется Git. Реальные официальные документы не включаются в репозиторий и не заменяются вымышленными.
- Загруженный документ становится доступен посетителям сразу после загрузки. Перед использованием сотрудник должен подтвердить актуальность и разрешение на публикацию.
- Для эксплуатации нужен антивирусный контроль документов и тест восстановления папки из резервной копии — отдельно от CI.

### 4. Календарь событий
- Публичная вкладка **«Календарь событий»**: сетка месяца, день недели, название мероприятий на дату, просмотр выбранного дня.
- Цвета мероприятий: **жёлтый — концерт, синий — спектакль, зелёный — фестиваль, сиреневый — другое**.
- Геометрические фигуры места: **★ концертный зал, ● танц-фойе, ■ театр «Орфей», 3-й этаж**.
- Цвет и форма сопровождаются текстовыми подписями в легенде и подробной карточке, чтобы не полагаться только на цвет.
- Вкладка администратора **«Календарь»**: название, дата, время, тип, место и описание. Создание черновика, сохранение, публикация и удаление.
- Текущее локальное хранилище `content/events/events.json`. В PostgreSQL предусмотрена миграция `004_cultural_events.sql`.
- Опубликованные мероприятия отображаются автоматически после обновления браузера (опрос примерно каждые 10 секунд). Неопубликованные записи не видны посетителям.
- Демонстрационные записи в тестах не являются реальными мероприятиями ДК и не публикуются на рабочий экран.

## Приёмка Windows

1. Остановить API и Vite, переключиться на `stage/05-3-documents-calendar-editor-fix`, выполнить `npm.cmd install --no-audit --no-fund`, затем `npm.cmd run check`.
2. Войти в редактор, открыть **«Расписание»**. Печатать в длинном текстовом поле более 8 секунд: курсор не должен исчезать, строка не должна обнуляться.
3. Перейти в соседнее поле: должно отобразиться **«Черновик сохранён»**. Повторно менять текст можно без нажатия на карточку.
4. Перейти во вкладку **«Страницы»**, повторить проверку, отдельно опубликовать и проверить посетительский экран.
5. Выйти из редактора, открыть гостевой вход и оставить без действий 3 минуты — переход к `/screen`. При активном вводе таймер должен сбрасываться.
6. На `/screen` проверить новую ссылку **«Вход в админку»**.
7. В редакторе **«Документы»** загрузить реальный актуальный DOCX с таблицей прейскуранта (не вымышленные цены), выбрать категорию, открыть в посетительском каталоге; проверить заголовки, таблицы, прокрутку и исходник.
8. Загрузить реальный PDF с положением или льготами; проверить встроенный просмотр и ссылку на оригинал. Убедиться, что пустые категории не показывают вымышленные документы.
9. В редакторе **«Календарь»** создать несколько тестовых записей на будущие даты, проверить, что до публикации посетительский календарь пуст; затем опубликовать.
10. Проверить цвета **4 типов** и фигуры **3 мест**, названия мероприятий внутри дат, стрелки переключения месяца.
11. Проверить дизайн на 1920×1080 и 1366×768 с каждой из восьми тем, включая длительные названия, выход за границы и 200% масштаб.
12. Перезапустить сервер API: календарь и документы должны сохраниться. Убедиться, что старые афиши, расписание и темы остались без изменений.

## Ограничения
- CI не запускает реальный PostgreSQL и не проверяет встроенный PDF-просмотр в Windows.
- Резервирование и антивирусная проверка новых загружаемых файлов — обязательный этап перед эксплуатацией на `DESKTOP-OBLAKO`.
- DOCX — семантическое преобразование, а не 100%-ная пиксельная копия Microsoft Word. Для сложной фирменной вёрстки рекомендуем PDF, а для интерактивной читаемости DOCX.
- При переходе на сервер использовать только HTTPS reverse proxy и нормальные учетные записи вместо временного пароля разработчика.
