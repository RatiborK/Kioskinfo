# Stage 05.5 — сенсорный киоск: афиша, поиск, Muzaticket, безопасность

## Результат
- «Афиша» полностью помещается на **одном экране**. Убраны подпись с названием файла и нижние миниатюры. Остались небольшие точки, номер афиши и компактная кнопка **«Купить билет»**.
- Свайп пальцем **влево / вправо** и приглушённые полупрозрачные стрелки по краям переключают изображения. Свайп вверх/вниз и касание не переключают.
- Кнопка с лупой открывает **глобальный поиск** без ухода со страницы; индексируются опубликованные коллективы (включая руководителей, расписание, кабинеты, группы), мероприятия и даты, документы по названию/категории, содержание памяток безопасности, афиши по названию, разделы «О ДК» и «Контакты», билетная касса. Поиск выполняется локально в браузере, без отправки строк в внешние поисковики.
- Убраны раздел и вкладка **«Расписание»**. Старые записи не удаляются. Утверждённые записи дополняют групповые карточки, но текст, уже написанный сотрудниками, не переписывается.
- В календаре сотрудников добавлено поле **ссылки Muzaticket** для каждого мероприятия. Если ссылка опубликована, на подробной карточке дня появляется кнопка покупки. Тип (цвет) и место (фигура) не меняются.
- **Покупка билетов**: отдельное контролируемое окно поверх НавиКультуры, с iframe `muzaticket.ru`. Кнопка на главной показывает официальный каталог ДК: `https://muzaticket.ru/iframe/organizations/organization-mau-gdk-kirovskii-448753`.
- В билетном iframe не разрешены popup и переходы верхнего окна; только браузерный платежный виджет. Фактическое прохождение оплаты, межсайтовые cookie и банковские редиректы необходимо проверить с оператором Muzaticket. Если провайдер запрещает iframe, он должен предоставить официальный код для интеграции с ограниченным киоском.
- Страница «Безопасность»: **15 текстовых памяток** с крупной типографикой, иллюстрациями, прокруткой и навигацией. Темы: пожар, эвакуация, противодействие коррупции, профилактика наркотической зависимости, ЗОЖ, антитеррор, мошенничество, ПДД, вода, площадки, открытый огонь, жестокое обращение, буллинг, дети и сопровождение, цифровая безопасность.
- В контактах **только текстовые строки**: никакого `tel:`, перехода на сайт или открывающейся вкладки. Видео коллектива и видеопрогулка ДК — отдельное внутреннее окно с ограниченным набором допустимых видеохостингов. Ссылки могут потребовать прямой формат embed.
- Публичный каталог и редактор получают расширенные темы при первом чтении **без перезаписи локального файла**, старые черновики сотрудников сохраняются.

## Что веб-приложение НЕ может гарантировать
Веб-страница не может надёжно скрыть браузерный интерфейс, заблокировать все системные сочетания клавиш или предотвратить выход в другие приложения. Эту границу обеспечивает **Windows Assigned Access** с Microsoft Edge, режим **Digital/Interactive Signage (fullscreen)**. Подтверждение: https://learn.microsoft.com/windows/configuration/kiosk/ и https://learn.microsoft.com/deployedge/microsoft-edge-configure-kiosk-mode

- Выделить **отдельную стандартную учётную запись Windows для посетителей**. Инженер/администратор входить в киоск должен через свою отдельную рабочую учётную запись.
- В `Настройки → Учётные записи → Другие пользователи → Киоск` выбрать Microsoft Edge и **«Цифровое / интерактивное табло», полноэкранный режим**.
- Адрес запуска в тестовом контуре — `http://127.0.0.1:5173/screen`, но при развёртывании из локальной сети нужен **реальный HTTPS URL** НавиКультуры. Локальный Vite + временный пароль нельзя публиковать в LAN.
- Политики браузера `URLBlocklist/URLAllowlist`, отключение всплывающих окон, скачиваний и инструментов разработчика настраиваются отдельно. Для встроенного билета потребуется разрешить нужные домены платёжных и билетных ресурсов; строгий запрет всех остальных должен быть протестирован.
- Windows оставляет системный, контролируемый способ выхода для администратора, например Ctrl+Alt+Del; это нормальная часть модели безопасности, а не дефект НавиКультуры.
- На этапе разработки **не включать Assigned Access на рабочем аккаунте**, не менять конфигурацию `DESKTOP-OBLAKO`.
- Проверять виджет Muzaticket только в тестовой покупательской сессии и не сохранять данные карт в логах/клиентском хранилище.

## Быстрый полноэкранный просмотр в VS Code
После запуска задачи `Navikultura: Start API + Web` запустить `Navikultura: Kiosk preview (Edge fullscreen)`. Она открывает установленный Microsoft Edge на `http://127.0.0.1:5173/screen` с `--kiosk --edge-kiosk-type=fullscreen --no-first-run`. Текущую Windows-учётную запись эта задача **не ограничивает**: это проверка внешнего вида без вкладок, а не надёжная защита от выхода. Для реального замыкания терминала нужен отдельный пользователь Assigned Access. Для корректного запуска режима иногда требуется закрыть уже запущенные окна Edge.

## Приёмка на личном Windows-ПК (без блокировки рабочего окружения)
1. Остановить старые Vite/API процессы, перейти на ветку `stage/05-5-kiosk-search-muzaticket`, выполнить `npm.cmd install --no-audit --no-fund`, `npm.cmd run check`.
2. Запустить в VS Code `Navikultura: Start API + Web`; открыть `http://127.0.0.1:5173/screen` на 1366×768 и 1920×1080. Главная афиша не прокручивается, изображение видно целиком (object-fit: contain), название файла на экране не показано.
3. Перелистнуть афишу пальцем/мышью влево и вправо, сравнить с тихими боковыми кнопками, проверить отсутствие случайных срабатываний при вертикальном движении.
4. Нажать «Купить билет»: появляется полноценное встроенное окно Muzaticket, **не новая вкладка**, с кнопкой «Вернуться в НавиКультуру». Если iframe блокируется провайдером, зафиксировать сообщение/скриншот и запросить у него официальный код виджета.
5. Открыть глобальный поиск: проверить запросы `Радуга`, `Арлекино`, `Палитра`, `Маков цвет`, `Кировский`, `Буллинг`, `Прейскурант`. Проверить поиск по фамилии руководителя, кабинету, календарю, документам и событиям.
6. Убедиться, что «Расписания» нет ни в меню, ни в табах администратора, но сведения и уже внесённые изменения сохранены в карточках коллективов.
7. В `/editor?tab=calendar` добавить мероприятие с отдельным `https://muzaticket.ru/iframe/...`, сохранить, опубликовать и проверить кнопку в подробностях даты. Невалидные сторонние домены должны быть отклонены сервером.
8. В разделе безопасности сверить содержание всех 15 памяток, заголовки и удобство прокрутки. Согласовать тексты с ответственным сотрудником ДК прежде чем использовать как официальные инструкции.
9. В контактах проверить отсутствие любых кликабельных номеров/сайтов. Из DOCX/PDF и видео нельзя уйти в другую вкладку.
10. Только на отдельной тестовой Windows-учётной записи проверить Microsoft Edge Assigned Access для интерактивного табло: отсутствие вкладок/адресной строки и ограничение выхода. При разработке использовать обычный браузер для отладки.

## Ограничения приёмки
- CI покрывает типы, сборку, контракты, фильтрацию, безопасность URL, сохранность опубликованных данных. Он **не подтверждает** физический свайп на сенсорном мониторе, отсутствие прокрутки на 1366×768, реальный виджет платежа и системную блокировку Windows.
- Встроенная оплата может потребовать интеграции от Muzaticket, т.к. внешние платёжные шлюзы иногда используют переходы, требующие особых разрешений браузера.
- Источники официальных памяток безопасности не заменяют локальные документы ДК: указанные материалы нужно утвердить на стороне учреждения.
