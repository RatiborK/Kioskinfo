# Stage 05.6.1 — вернули наполнение и тематические значки меню

## Что исправлено

### Наполнение не исчезло из Git
В ветке Stage 05.6 сохранены **37 исходных коллективов и 30 руководителей**, категории, история ДК, контакты, 17 новых тематических памяток, документы и афиши в отдельных хранилищах. Пользовательские изменения находятся локально в `content/culture/catalog.json` (не отслеживается Git) или в PostgreSQL; коммиты их не удаляют.

### Причина возможной пустой страницы
Ранее GET `/api/public/culture` и GET `/api/editor/culture` зависели от `schedule.list()`. После скрытия старого расписания сбой его файлового хранилища всё равно мог вызвать HTTP 500 и скрыть весь каталог. Теперь расписание является **необязательным источником обогащения**, и при его сбое API возвращает сохранённый каталог без потери фотографий, биографий, коллективов, истории и памяток.

Preview-API больше не отказывается запускаться, если одноразовое создание устаревших расписаний ошибочно. Публичный экран в случае другой ошибки показывает предупреждение и кнопку «Повторить загрузку» вместо пустого места.

### Сохранность данных
- Сбой парсинга локального `catalog.json` при новом запуске больше не подменяет сохранённое наполнение стартовым каталогом. Файл остаётся на месте, ошибка становится заметной.
- При успешной записи каталог оставляет копию предыдущего сохранённого состояния: `content/culture/catalog.json.previous`.
- Обновление старых памяток теперь **сохраняет все пользовательские темы**, в том числе прежние `objects`, `health`, и добавляет новые темы только при отсутствии; все заголовки и абзацы сотрудников остаются.
- В кабинете `/editor?tab=culture` вкладка **«Наполнение ДК» теперь первая**.
- Кнопка **«Восстановить наполнение»** доступна администратору: добавляет *только отсутствующие* исходные коллективы, категории, руководителей и памятки; имеющиеся не изменяет. Сохраняется черновик, посетительский экран обновится лишь после отдельной публикации. Если все исходные материалы уже есть — кнопка ничего не перезаписывает.
- Редактор не скрывает успешную авторизацию только из-за ошибки загрузки списка страниц.

### Тематическое меню
Оригинальные значки **«Афиша» (✦) и «Календарь» (▦) не тронуты**.
Остальные заменены на аккуратные SVG:
- **Коллективы** — театральные маски;
- **Документы ДК** — развёрнутый документ/свиток;
- **Безопасность** — щит с галочкой;
- **О ДК** — здание Дворца культуры;
- **Контакты** — информационная карточка;
- **Навигация** — поэтажный план.

Иконки показываются на мобильной/сенсорной ширине тоже, поддерживают все восемь тем, размеры кнопок соответствуют предыдущим. Названия разделов и маршруты навигации не изменены.

## Проверить локально без потери данных

1. Остановить оба сервера в VS Code через Ctrl+C.
2. В PowerShell из `C:\Users\<user>\Navikultura` проверить наличие локального каталога: `Test-Path -LiteralPath './content/culture/catalog.json'`. **Ничего не удалять.**
3. Перейти на `stage/05-6-1-content-restore-themed-menu`, `npm.cmd install --no-audit --no-fund`, `npm.cmd run check`.
4. Запустить задачу `Navikultura: Start API + Web`.
5. Открыть `http://127.0.0.1:5173/screen`, затем раздел «Коллективы» — должен быть каталог с прежними профилями.
6. Перейти в `/editor?tab=culture`. Если данные есть — **ничего восстанавливать не нужно**, просто продолжайте правки. Если есть отсутствующие исходные записи — нажмите «Восстановить наполнение», затем после проверки «Опубликовать на экране».
7. Проверить иконки в меню на 1366×768 и 1920×1080.
8. Для диагностики публичного каталога команда PowerShell без авторизации:
   `$r=Invoke-RestMethod -Uri 'http://127.0.0.1:3100/api/public/culture'; [pscustomobject]@{Collectives=$r.content.collectives.Count;Leaders=$r.content.leaders.Count;Safety=$r.content.safety.sections.Count;Revision=$r.revision}`

## Что нельзя восстановить из публичного Git
Удалённые вручную фотографии, документы и изменения конкретных сотрудников, которых нет в локальном каталоге, предыдущем снапшоте, файловых резервных копиях или PostgreSQL, не содержатся в Git. Поэтому автоматический сброс каталога запрещён. При повреждённом `catalog.json` требуется сначала безопасно проверить его и старые копии, не запускать полную перезапись.

`main` и компьютер `DESKTOP-OBLAKO` не изменены.
