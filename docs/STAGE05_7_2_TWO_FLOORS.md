# Stage 05.7.2 — два этажа в навигации ДК

## Изменение по запросу учреждения

На странице «Навигация» и в редакторе «Наполнение ДК → Планы ДК» теперь **ровно две схемы**:

1. **Первый этаж** — исходный план `floor-1.webp`.
2. **Второй этаж** — ранее опубликованная схема **«Схема с обозначениями»** с исходным файлом `floor-3.webp`.

Кнопка **«Схема верхнего уровня»** (исходный `floor-2.webp`) скрыта. Третий этаж и обозначения кабинетов будут добавлены отдельно, после предоставления планов и уточнения точек.

## Сохранность данных

- Файл `floor-2.webp` не удаляется; он остаётся в локальном архиве ассетов.
- `content/culture/catalog.json` и PostgreSQL **не изменяются миграциями**. Исторические записи `floor-2`, `floor-3` и все существующие точки остаются в сохранённом состоянии.
- Идентификатор `floor-3` по-прежнему соответствует существующему изображению `floor-3.webp`; только его **публичное название** стало «Второй этаж». Это избавляет от опасной перенумерации точек и карт.
- Навигационный поиск индексирует только активные планы и их метки; скрытая схема и её точки не будут появляться в результатах.
- В админке доступны только активные планы; старые записи не удалены из базы, чтобы восстановление при необходимости было обратимым.
- Для новых установок стартовый текст у второй отображаемой схемы обновлён. В существующих данных пользовательские примечания сохраняются. Старое примечание «этаж уточняется» заменяется только на экране.

## Приёмка

1. Переключиться на `stage/05-7-2-two-floor-navigation` после остановки API/Vite, запустить `npm.cmd run check`.
2. Запустить локальный preview API на 3100 и Vite на 5173, как в предыдущем этапе.
3. Посетитель: `/screen` → **Навигация** — только две кнопки «Первый этаж» и «Второй этаж».
4. Выбрать «Второй этаж»: должна открыться **та же схема с обозначениями**, которая ранее была третьей вкладкой; карта не должна растягиваться с неправильными пропорциями.
5. Убедиться, что «Схема верхнего уровня» не отображается ни в публичных вкладках, ни в редакторе, ни в результатах поиска.
6. Редактор: `/editor?tab=culture` → **Планы ДК** — два активных плана, функциональность добавления точек и сохранения черновиков работает.
7. Сохранённое наполнение: сверить каталог `/api/public/culture`; данные коллективов/руководителей остаются прежними.

**Третий этаж** и подробное обозначение кабинетов — отдельный будущий этап с уточнённой схемой. До этого не добавлять на план непроверенные помещения или эвакуационные маршруты.

`main`, `DESKTOP-OBLAKO` и текущие документы ДК не затронуты.
