# Stage 05.8.1 — прозрачный логотип, документы, браузер и админка

## Состав изменений

- Компонент логотипа рисует ту же **утверждённую геометрию пяти полигонов**, что печатный файл `public/brand/dk-kirovsky-symbol.svg`. Два цветных полигона остаются `#FF7900` и `#0874FF`; вместо трёх чёрных полигонов используется `currentColor`. Текстовая часть тоже наследует контрастный цвет. Белой плашки нет. Исходный печатный SVG и favicon не изменены.
- Светлый фирменный цвет включается на тёмных темах `dk/holiday/modern/aurora/neon` и в тёмной редакторской оболочке. На светлых темах используется тёмный цвет.
- Световое пятно на теме ДК перенесено с пересоздаваемой страницы на постоянный `.screen-shell::before`: переключение разделов больше не перезапускает цикл анимации в 46 секунд. При `prefers-reduced-motion` движение отключается.
- У значков меню удалён glow/drop-shadow, но фирменные двухцветные SVG сохранены.
- Форма входа запрашивает `autocomplete="off"`; браузер может всё равно предлагать сохранение паролей, поэтому запрет на эксплуатационном ПК делается политикой Edge, см. ниже.
- Раскладка веб-клавиатуры формы входа фиксирована по рядам без переноса кириллических клавиш; адаптивно сжимается и допускает горизонтальную прокрутку на узком экране.
- В админке появилась кнопка **«Полный экран»** (Fullscreen API). Маршрут «Экран посетителя» использует Vue Router без перезагрузки, поэтому сохранённый браузером fullscreen не теряется при переходе.
- В «Темы оформления» администратор может сохранить серверную настройку «Предлагать полноэкранный режим на экране посетителя». Она хранится с ревизией в существующем репозитории тем и дополнена колонкой `fullscreen_enabled` PostgreSQL через новую миграцию `006_kiosk_fullscreen.sql`. Роли editor/viewer не могут её менять.
- По умолчанию настройка отключена; на странице посетителя при её включении отображается кнопка и первая попытка происходит по пользовательскому жесту.
- При открытии PDF в разделе «Документы» блок «Все документы», тип и название отображаются **слева под заголовком «Документы»**, а PDF занимает правую колонку почти с верхней границы страницы. Для экранов шириной до 1100px интерфейс складывается вертикально. Исходный PDF не меняется.

## Полноэкранный режим: границы браузера

Fullscreen API **не имитирует нажатие F11** и обычно требует нажатия/касания на странице. Настройка админки не может сама обойти ограничение браузера, поэтому автоматическое открытие на холодном старте гарантируется лишь через управляемые настройки Edge или Windows Assigned Access. Это не изменение системных политик на компьютере.

Для управляемого Edge версии 132+ Microsoft документирует политику `AutomaticFullscreenAllowedForUrls` для доверенных origins:
https://learn.microsoft.com/en-us/deployedge/microsoft-edge-browser-policies/automaticfullscreenallowedforurls

Для production терминала предпочтителен Edge Assigned Access: https://learn.microsoft.com/en-us/windows/configuration/kiosk/

## Пароли и автозаполнение

HTML `autocomplete=off` — пожелание для браузера, а не защита от встроенного менеджера паролей. На выделенной учётной записи киоска с правами администратора Windows отключить менеджер паролей и автозаполнение Edge централизованными политиками. Использовать отдельную учётную запись посетителя, не разделять браузерный профиль с сотрудниками.

Одна строка PowerShell **на выделенном терминале с повышенными правами**, после предварительного согласования политик с системным администратором:

```powershell
& { $p='HKLM:\SOFTWARE\Policies\Microsoft\Edge'; New-Item -Path $p -Force | Out-Null; New-ItemProperty -Path $p -Name PasswordManagerEnabled -PropertyType DWord -Value 0 -Force | Out-Null; New-ItemProperty -Path $p -Name AutofillAddressEnabled -PropertyType DWord -Value 0 -Force | Out-Null; New-ItemProperty -Path $p -Name AutofillCreditCardEnabled -PropertyType DWord -Value 0 -Force | Out-Null; Write-Host 'Edge password manager and autofill disabled' }
```

После применения перезапустить Edge, открыть `edge://policy` и убедиться, что политики действуют. Существующие сохранённые пароли **не удаляются** этими настройками. Использовать отдельный чистый профиль киоска.

## Windows OSK и Edge Local Network Access

Пример пользовательского вывода `Windows keyboard bridge listening on http://127.0.0.1:48765` показывает только запуск локального помощника, **но не доступ браузера к нему**.

1. Проверить, что вспомогательный процесс работает **на том же ПК**, где открыт `/screen`.
2. Сравнить реальный origin (схема, хост, порт) с `Allowed origins`. Для публикации HTTPS указать реальный сайт в `NAVIKULTURA_KIOSK_ORIGIN`; не использовать `*`.
3. Microsoft Edge 143+ может запросить разрешение **«Доступ к локальной сети»**; выдать его только сайту НавиКультуры. Проверить `edge://settings/content/localNetworkAccess` или разрешения открытого сайта и `edge://policy`.
4. Если мост вернул HTTP 403, он работает, но origin/Host не совпал. Если HTTP 503 — см. доступность `osk.exe` в пользовательской сессии Windows. Если ошибка сети — возможны политика Edge, CORS или отсутствие helper.
5. Системная сенсорная клавиатура Windows при физическом касании поля Muzaticket — отдельный вариант, который нужно проверить на реальном сенсорном оборудовании.

Справка Microsoft: https://learn.microsoft.com/en-us/deployedge/ms-edge-local-network-access

## Приёмка

1. На новой ветке выполнить `npm.cmd run check`; ожидать CI PASS.
2. Проверить логотип на каждой светлой и тёмной теме, включая превью и страницу входа. Красный/синий цвета знака не должны измениться.
3. Переключаться между страницами/нажимать кнопки и наблюдать 46-секундное пятно — оно не должно прыгать в начальную позицию. Учитывать `prefers-reduced-motion`.
4. Проверить отсутствие подсветки иконок меню, сохранить двухцветную графику.
5. Войти в админку; проверить клавиатуру РУ/EN, стирание, компактность и отсутствие переноса на 1366×768 и 1920×1080.
6. Нажать «Полный экран», открыть «Экран посетителя» без перезагрузки маршрута; полный экран должен сохраниться. Нажать Escape — выход из режима.
7. Администратор: включить флаг полноэкранности, обновить страницу, убедиться, что он сохранён, а editor/viewer не могут изменить его. На публичном экране должна появиться кнопка; проверить жест и ограничение без жеста.
8. Открыть «Документы» → PDF «Льготы»: навигация/подзаголовок слева, PDF справа начиная сверху. Узкое окно — вертикальный режим без горизонтального выхода за экран.
9. Проверить менеджер паролей и автозаполнение именно в профиле киоска Edge; HTML-атрибут не является полным запретом.
10. Проверить на Windows-терминале кнопку OSK; не распространять localhost-helper на LAN и не менять файловый сервер `DESKTOP-OBLAKO`.

Новые функциональные изменения требуют физической проверки. CI не подтверждает работоспособность Windows Assigned Access и Muzaticket.
