# Stage 05.8 — тёмная тема ДК и Windows-клавиатура в Muzaticket

## Дизайн
- Только опубликованная тема `dk` меняет базовые цвета: `#2c3e50` (фон), `#273a4b` (навигация), `#344b5f` (карточки).
- Существующие `#ff6a00` (оранжевый), `#065cbd` (синий) и две краски SVG-значков остаются неизменными.
- На фоне — узкие полупрозрачные вертикальные линии и рассеянное пятно `#4ca1af`; движение верхней части занимает 46 секунд.
- Анимация использует только transform и отключается через `prefers-reduced-motion: reduce`.
- Логотип сохраняет фирменную белую подложку. Реальные афиши и исходные планы помещений не перекрашиваются.
- Остальные семь тем, редактор сотрудника и опубликованные записи не меняются.

## Почему невозможно запускать системную клавиатуру через iframe

Muzaticket загружается с другого origin в ограниченном iframe. Код НавиКультуры
не может прочитать и фокусировать его поля, отправлять им нажатия или напрямую
запустить приложение Windows. Имеются два независимых пути:

1. **Основной:** системная Windows Touch Keyboard появляется при касании текстового поля
   на устройстве с сенсорным экраном без физической клавиатуры в режиме Assigned Access.
   Для проверки требуется именно прикосновение, не обычный клик мышью.
2. **Дополнительный явный вызов:** кнопка «Клавиатура Windows» отправляет `POST`
   на `http://127.0.0.1:48765/keyboard`. Только локальный компонент на том же
   Windows-компьютере запускает `osk.exe`, не читая и не передавая содержимое полей.

Документация Microsoft по автоматической сенсорной клавиатуре:
https://learn.microsoft.com/en-us/windows/configuration/assigned-access/configure-single-app-kiosk

## Пробный запуск локального компонента на Windows

**На компьютере, где посетитель видит экран НавиКультуры,** обновить рабочую копию проекта
до ветки Stage 05.8. Нужен установленный Node.js версии 26 по требованиям проекта.

Для локального запуска Vite с адресом `http://127.0.0.1:5173/screen`
в отдельном PowerShell-окне выполнить одной строкой:

```powershell
Set-Location "$env:USERPROFILE\Navikultura"; node .\tools\kiosk-windows-keyboard.cjs
```

Для опубликованного HTTPS-сайта **вместо примера** указать реально используемый origin;
до развёртывания сайта примерный адрес `https://navikultura.local` не действует:

```powershell
Set-Location "$env:USERPROFILE\Navikultura"; $env:NAVIKULTURA_KIOSK_ORIGIN='https://navikultura.local'; node .\tools\kiosk-windows-keyboard.cjs
```

Процесс должен оставаться работающим в интерактивной Windows-сессии киоска.
Закрытие PowerShell прекращает работу компонента. Это не Windows-служба и не автозапуск.
Не запускать на `DESKTOP-OBLAKO` как на сервере, если он не является тем же
физическим терминалом с экраном.

### Безопасность
- Сервер слушает **только 127.0.0.1**; никакого LAN-порта или произвольной команды.
- Допускаются только точные разрешённые origins (локальная разработка или явно заданные через `NAVIKULTURA_KIOSK_ORIGIN` HTTPS-адреса), корректный Host, точный путь, POST и нестандартный заголовок действия.
- Никакие пользовательские URL и аргументы не передаются `osk.exe`.
- Кросс-доменные запросы проходят CORS. Из-за требований Chromium Local Network Access современный Edge может дополнительно запросить разрешение доступа сайта к локальному устройству.
- Для управляемых ПК инженер может настроить Edge policy `LocalNetworkAccessAllowedForUrls`
  только для реального доверенного origin, а затем проверить через `edge://policy`.
  Не разрешать `*` и не редактировать политики автоматически.
- `osk.exe` может быть ограничен режимом Assigned Access; физическая приёмка обязательна.
- Если локальный компонент недоступен, приложение показывает причину и не изображает успешный запуск.

Справка о Local Network Access:
https://developer.chrome.com/docs/modern-web-guidance/guides/security/local-network-access

Политики Microsoft Edge:
https://learn.microsoft.com/en-us/deployedge/microsoft-edge-policies/localnetworkaccessallowedforurls

## Проверка
1. `npm.cmd run check` — проверка типов, клиентских и серверных тестов, и тестов Windows-моста без ОС Windows.
2. Открыть `/editor?tab=themes`: тема «Стиль сайта ДК» имеет тёмный предпросмотр и медленное бирюзовое движение.
3. Показать тему `dk` на `/screen`: тонкие полосы, верхнее свечение, светлый текст и прежние оранжево-синие значки.
4. В Windows включить режим сокращённой анимации: пятно остаётся на месте.
5. Проверить 1920×1080, 1366×768, а также читаемость при разной освещённости и в меню.
6. Открыть Muzaticket, нажать кнопку «Клавиатура Windows» на реальном Windows-терминале: при работающем helper появляется системный `osk.exe`.
7. Остановить helper, нажать ещё раз: отображается понятная ошибка, покупка билетов не закрывается.
8. Без helper проверить автоматическую Windows Touch Keyboard при **физическом касании** поля внутри iframe без физической клавиатуры.
9. При использовании Assigned Access отдельно проверить, что клавиатура отображается поверх Edge, не даёт выйти из режима киоска и что переходы оплаты по-прежнему работают.
10. На клиентском устройстве проверить при необходимости настройки разрешений Edge для loopback; не открывать компонент для всей LAN.

## Статус
GitHub PR/CI и лабораторные проверки не доказывают работу `osk.exe` внутри
целевого Windows Assigned Access. Развёртывание на рабочий терминал
разрешается только после ручной проверки и штатного резервного копирования.
