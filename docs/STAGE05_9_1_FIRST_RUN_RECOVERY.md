# Stage 05.9.1 — исправление «Настройка недоступна» в переносимом EXE

## Симптом

Сборка `Navikultura-0.4.0-Windows-x64.exe` открывает первый запуск, принимает два пароля, затем показывает «Настройка недоступна».

Сообщение было общим для **разных причин**: main-frame IPC отклонён из-за проверки объекта `event.senderFrame !== webContents.mainFrame` либо `admin.json` уже записан и повторная попытка заблокирована, но окно ещё не перешло на `/screen`. Один скриншот не позволяет отличить случаи.

## Исправление

- `desktop/lib/trust.cjs` проверяет неизменяемый WebContents, идентификатор дерева кадра либо пару process/routing ID, отсутствие родителя и строгий путь `file://.../first-run.html`. Независимые JS-обёртки одного main-frame теперь допускаются; вложенные iframe и сторонние страницы запрещены.
- Отказ из-за чужого IPC-кадра имеет отдельный код `UNTRUSTED_FRAME` и понятное сообщение.
- Если профиль администратора **уже создан**, повторная кнопка не пытается перезаписать пароль, а направляет посетителя к `/screen`. Используется ранее указанный пароль.
- Переход выполняется после отдачи ответа IPC, чтобы не уничтожать вызывающий renderer до разрешения promise.
- Защита от одновременных нажатий `initializingAdmin`.
- **Данные не сбрасываются**: `%APPDATA%\НавиКультура\data\state\admin.json` и опубликованный контент не удаляются.
- В `--smoke-onboarding` Windows CI реально открывает `first-run.html` в Electron с preload, вызывает `window.navikulturaDesktop.setupAdmin`, проверяет переход на `/screen` и сохранение хеша пароля в тестовой временной папке. Это проверка гораздо точнее, чем предыдущий smoke только API/SPA.

## Запуск и диагностика

1. Скачать EXE 0.4.1 из GitHub Actions соответствующего PR (один файл внутри ZIP).
2. Закрыть старый EXE (`Ctrl+Shift+Q` и подтверждение), скопировать новую версию в обычную папку и запустить двойным щелчком.
3. Если пароль ещё не сохранён — создать его на экране первого запуска. Если сохранён ранее — открывается посетительский экран, а в админку входить под `admin` и **старым** паролем.
4. Проверить создание нового профиля на чистой учётной записи Windows (не удаляя текущие данные).
5. Если первая настройка снова отклонена, сообщить **точный текст и код ошибки**, новую сборку не очищать.
6. На настоящем сенсорном мониторе проверить виртуальную клавиатуру, полноэкранность и ввод без мыши.

Независимое CI-тестирование не заменяет реальную приёмку на конкретном терминале с Windows и сенсорным экраном. Неподписанный EXE может вызвать SmartScreen.
