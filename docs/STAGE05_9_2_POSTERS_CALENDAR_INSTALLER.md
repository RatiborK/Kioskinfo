# Stage 05.9.2 — независимая загрузка афиш, восстановление календаря, стрелка вниз и установщик

## 1. Афиши: 20 МиБ, каждый файл отдельно
Теперь браузер отправляет **один бинарный POST на одну афишу**:
`POST /api/editor/posters/upload`, заголовки `Content-Type: application/octet-stream`,
`X-Navikultura-Action: 1` и `X-Navikultura-File-Name: <percent-encoded filename>`.
Нет Base64 увеличения и прежнего 11 МБ JSON-ограничения. Fastify проверяет тело на уровне маршрута:
`bodyLimit=20*1024*1024`. Разрешены JPG/JPEG, PNG, WebP, GIF (включая анимацию),
AVIF, BMP. Запрещены SVG и HEIC без преобразования: их безопасное воспроизведение
в браузере не подтверждено. Сервер проверяет расширение, допустимость имени, сигнатуру,
строгий размер, а затем сохраняет файл атомарно в пользовательский каталог.

В редакторе `/editor?tab=posters` под загрузкой появляется отдельная строка для каждого файла:
«В очереди», «Загружается», «Добавлена» или «Ошибка: причина».
**Ошибка одного файла не прерывает пакет**: следующий отправляется независимо.
Показываются количество обработанных/успешных/отклонённых файлов.

При ошибках диска API возвращает `500` с объяснением возможной проблемы записи
в локальное хранилище, а не только обобщённое «Обратитесь к администратору».
До 20 МиБ — это лимит файла, а не суммарный лимит выбранного пакета.

## 2. Календарь
Исправлен CSS `.visitor-calendar-page`, который наследовал от `.schedule-section`
`flex:1` и `overflow:auto`, сжимая сетку на экране. Календарь теперь имеет
семь колонок, полноценные ряды **не менее 114px** для 1920px, не менее 100px
на планшетах и не менее 82px на узком экране. Страница целиком скроллится
пальцем; ниже находится карточка выбранного дня. Сравнение — второй
скриншот пользователя, не первый (сплющенный).

## 3. Ненавязчивая подсказка прокрутки
`/screen`: когда в активном разделе под видимой областью есть ещё содержимое,
внизу посетительской зоны появляется полупрозрачная стрелка вниз.
Одна плавная пульсация прозрачности длится 4.2 секунды, без яркого glow/прыжков.
При прокрутке к низу стрелка исчезает; при возврате наверх появляется снова.
На афише и поверх билетного, видео- и поискового окон стрелка не показывается.
Нажатие прокручивает страницу примерно на 75% высоты. Respect `prefers-reduced-motion`.

## 4. Windows 0.4.2: установщик и переносимая версия
GitHub Actions собирает два отдельных EXE:
- `Navikultura-0.4.2-Setup-Windows-x64.exe`: инсталлятор NSIS в профиль
  Windows с ярлыком на рабочем столе, без прав администратора;
- `Navikultura-0.4.2-Portable-Windows-x64.exe`: единый переносимый файл
  без установки.

Оба используют **одинаковый каталог пользовательских данных**, ранее созданный
версией 0.4.1. Нельзя удалять пользовательские данные при обновлении/деинсталляции.
NSIS также оставляет данные (`deleteAppDataOnUninstall:false`).
Smoke-тесты запуска API и первичной регистрации остаются обязательными.

## 5. Схемы этажей не лежат в публичном GitHub
Оригинальные схемы перенесены из `план дк.vsdx` при Stage 05.6
в отдельный приватный архив `Navikultura_Stage056_Media.zip`:
- **Первый этаж** — `apps/web/public/assets/navigation/floor-1.webp`.
- **Второй этаж** — исходная «схема с обозначениями»,
  `apps/web/public/assets/navigation/floor-3.webp` (переименована публично
  на Stage 05.7.2 без переименования файла). `floor-2.webp` скрыт.

Эти планировки **нельзя заменить выдуманной картой** и нельзя автоматически
добавить в публичный GitHub без согласования. Для передачи двух существующих
изображений пользователю с его собственного Windows ПК можно выполнить
одну PowerShell-команду (не требует редактора, не изменяет оригиналы):

```powershell
& { $src=Join-Path $env:USERPROFILE 'Navikultura\apps\web\public\assets\navigation'; $out=Join-Path $env:USERPROFILE 'Downloads\НавиКультура_Планы_этажей'; New-Item -Path $out -ItemType Directory -Force | Out-Null; foreach($p in @(@('floor-1.webp','Первый этаж.webp'),@('floor-3.webp','Второй этаж.webp'))){$f=Join-Path $src $p[0]; if(!(Test-Path -LiteralPath $f -PathType Leaf)){throw "План отсутствует: $f — распакуйте локальный архив Stage056_Media.zip"}; Copy-Item -LiteralPath $f -Destination (Join-Path $out $p[1]) -Force}; Get-ChildItem -LiteralPath $out -File | Select-Object Name,Length,FullName }
```

Если оба исходника будут предоставлены в этой беседе, можно приложить их как два
файла пользователю. GitHub CI их не видит; собранный установщик не включает
локальные пользовательские floor-планы, пока не подключён отдельный
защищённый канал поставки медиафайлов.

## Приёмка
1. `npm run check` плюс API-тесты прав, подписи JPG/GIF/AVIF/BMP, размера 20 МиБ,
   проверка ошибки одного файла и успеха следующего.
2. `Windows Installer and Portable` CI: build обоих EXE, smoke встроенного
   API, действительный IPC первого запуска и проверка артефактов/хеша.
3. В реальном терминале 1920×1080 и 1366×768 проверить календарь 7 колонок
   и высоту 114/100px, прокрутку пальцем.
4. Проверить стрелку при длинной странице, у низа, при показе видео и оплате,
   при настройке reduced motion.
5. Загрузить 12 предоставленных изображений одновременно, преднамеренно добавив
   один неподдерживаемый файл в середину: остальные обязаны загрузиться.
6. Установить `Setup` поверх ранее установленного приложения/переносимой версии
   и убедиться в сохранении афиш, админа, темы и локальных видео.
