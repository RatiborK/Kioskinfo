# НавиКультура — восемь готовых тем для посетителей (Stage 05)

## Продуктовое решение
Настройки оформления не принадлежат отдельной карточке. Во вкладке **«Темы оформления»** сотрудник выбирает единый образ для всей посетительской системы. Администратор утверждает его кнопкой **«Опубликовать тему»**.

| ID | Название | Характер |
|---|---|---|
| dk | Стиль сайта ДК | Тёмная база с оранжевым и синим, узнаваемая палитра проекта |
| holiday | Праздничная | Бордовый и тёплое золото, мягкие статичные огни |
| modern | Стильная | Монохром, чистая типографика, минимум декора |
| aurora | Северное сияние | Глубокая синь, бирюзовые световые градиенты |
| poster | Афишная | Светлая бумага, насыщенная типографика |
| gallery | Галерея | Светло-зелёная и кремовая палитра, сдержанные карточки |
| neon | Неон-сцена | Ночной концертный свет, контрастные акценты |
| kids | Детская мастерская | Мягкие формы, светлая радостная палитра |

Все стили управляются **закрытым перечнем ID**. Не допускается ввод произвольного CSS, HTML, удалённых URL или JavaScript через редактор. Фотографии афиш не подвергаются перекрашиванию: оформляется *оболочка*, а не оригинал изображения.

## Принципы оформления, на которых основана реализация

Изучены рекомендации:
- W3C WCAG 2.2: 1.4.3 — контраст обычного текста от 4.5:1, крупного от 3:1; 2.5.8 — размер сенсорных целей не менее 24×24 CSS px (важные элементы проектируем крупнее), 1.4.1 — цвет не единственный сигнал
- W3C WCAG 2.2: 2.3.1 — избегать мигания; 2.3.3 и prefers-reduced-motion — учитывать чувствительность к анимации
- Material Design 3: палитры через семантические роли фона, поверхности, основного текста, акцента и текста на акценте

Проверен программно контраст следующих **заявленных пар** во всех восьми палитрах: основной текст/фон, вторичный текст/фон и поверхность карточки, текст/навигация, текст/акцент. Минимальная измеренная величина для этих пар — 5.52:1. Это не означает завершённую полную проверку WCAG для всех элементов — она нужна отдельно на реальных экранах.

## Хранение и публикация

- Локальная разработка: `content/settings/visitor-theme.json` (игнорируется Git), безопасная атомарная запись, сохранность после перезапуска
- Сервер: PostgreSQL, миграция `003_visitor_themes.sql`, таблица `visitor_theme_settings`
- `GET /api/public/theme`: только опубликованная тема
- `GET /api/editor/theme`: после входа настройки и список вариантов
- `PATCH /api/editor/theme`: admin/editor выбирает черновик по ревизии
- `POST /api/editor/theme/publish`: только admin публикует выбранную тему
- Контроль ревизии защищает от тихой перезаписи при одновременной работе
- Экран `/screen` проверяет обновление темы раз в 10 секунд без перезапуска; при сетевой ошибке остаётся последняя известная тема
- Существующие афиши, карточки и текст страниц не изменяются

## Приёмка на ПК разработки

1. Запустить локальный API и Vite и войти в `http://127.0.0.1:5173/editor?tab=themes`
2. Проверить восемь предпросмотров и выделение выбранного
3. Сменить тему на «Праздничную»; до сохранения и публикации экран посетителя не меняется
4. Нажать «Сохранить выбор» — публичный экран по-прежнему в прежнем стиле
5. Нажать «Опубликовать тему» — в пределах 10 секунд меняются фон, меню, заголовки, карточки на `/screen`
6. Проверить каждую из 8 тем в афишах, расписании и карточке коллектива
7. Перезапустить API: опубликованный вариант остаётся прежним
8. Проверить доступ viewer (без сохранения), editor (без публикации), admin (с публикацией)
9. Проверить размер 1920×1080, 1366×768 и узкое окно, читаемость, длинные названия, фокус клавиатуры
10. Провести отдельный WCAG-проход, контраст focus/hover, 200% масштаб и сенсорное взаимодействие
11. Проверить, что предыдущие `content/schedule/records.json` и `content/posters/` остались нетронутыми

## Технический долг

Поля `theme` и `inheritTheme` в старом контракте расписания временно остаются ради обратной совместимости, но больше не влияют на посетительское оформление и не показываются в веб-форме. Удалять их из существующих записей без миграции нельзя.
